# `.claude/workflow.json`

Per-project configuration read by every dw agent and skill. Generated by `/dw:bootstrap`, versioned in the project, contains **no secret**. Formal schema: `workflow.schema.json` (same folder).

## Fields

| Field | Meaning |
| :- | :- |
| `version` | Schema version, always `1`. |
| `language` | Language of every human-facing output: Linear issues and comments, `docs/`, QA reports, PR titles and bodies, chat with the user. Agent instructions stay in English. |
| `linear.team` | Linear team key or name. |
| `linear.project` | Current working Project, default scope of `/dw:run`. Chosen or created by `/dw:bootstrap` (it holds the Foundations tickets on an empty project); `/dw:epic` offers to switch it to the Project it creates. `null` = every Project of the team. |
| `linear.statuses.<role>` | Exact name of the Linear workflow state playing that role. Agents always go through the role, never a hard-coded name. Roles and transitions: `state-machine.md`. |
| `linear.labels.<role>` | `story` = user story issue (product-engineer), `ticket` = technical ticket `/dw:run` can pick (em), `escalated` = QA loop exhausted, human needed. |
| `forge.type` | Adapter in `reference/forges/<type>.md`. Shipped: `github`. |
| `forge.remote` | git remote for `fetch`, `pull`, `push`. |
| `forge.host` | Optional web host for links (adapter default otherwise). |
| `forge.owner`, `forge.repo` | Repository coordinates on the forge. |
| `forge.baseBranch` | Branch every ticket starts from and every PR targets. Pushing to it is blocked by the dw guard hook. |
| `packageManager` | `pnpm`, `npm`, `yarn` or `bun`. |
| `monorepo.tool` | `turborepo`, `nx`, `workspaces` or `none`. |
| `env.start` / `env.stop` | Start/stop local dependencies (Postgres in Docker). Run before integration tests. |
| `apps[]` | One entry per app or package. `path` uses forward slashes from the repo root. `label` is the Linear label put on tickets touching it. `commands.*` run from the repo root; `null` means the command does not exist for that app. |
| `qa.maxIterations` | Max dev ↔ QA round trips per ticket before escalation (default 3). |
| `docs.root` | Documentation root (default `docs`). Layout: `docs-conventions.md`. |

## How agents use it

1. Read `.claude/workflow.json` first. If it is missing, stop and ask the user to run `/dw:bootstrap`.
2. Resolve Linear state and label names through `linear.statuses` / `linear.labels`.
3. Resolve git remote and base branch through `forge.remote` / `forge.baseBranch`.
4. Resolve PR operations through `reference/forges/<forge.type>.md`.
5. Map changed files to apps by longest `apps[].path` prefix to decide which commands to run ("impacted apps"). A change under a `package` impacts the package and every app whose `package.json` depends on it; when in doubt run the commands of all apps. Changes outside every `apps[].path` (root config, lockfile, CI) impact all apps.
